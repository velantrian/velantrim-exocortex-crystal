# 📚 Velantrim Documentation Standard v1

`overview != current state != evidence != history`

- `STRUCTURAL_CHANGE`: review all maintained landing surfaces and refresh only the representations whose meaning became stale.
- `STATE_CHANGE`: remove stale high-level state implications and refresh current-state surfaces.
- `EVIDENCE_ONLY`: update evidence/checkpoints without unnecessary visual churn.

Visual roles are distinct: Tree = what exists; Mindmap = concept relations; ASCII = information/authority flow; Table = may/must-not boundary; Commentary = architecture rationale.

Machine navigation: `project_manifest.yaml`. Technical truth remains in merged code, tests/CI, `CURRENT_STATE.md` and `docs/status/implementation-manifest.json`.
